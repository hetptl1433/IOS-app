# SPARC for iPhone

A native SwiftUI iOS 17+ app, using the approved SPARC design:
pitch-black backgrounds, neutral glossy cards, dark green data, and the realistic
Cybertruck cutout with a separate animated white front light. The light turns on
only while charging and respects Reduce Motion.

The user's local app checkout belongs at `~/Documents/project/sparc APP`.
The sibling `sparc` directory is a different project; do not replace or merge it.
See [current status and continuation notes](../docs/ios/STATUS.md) for verified
results and remaining hardware/release work.

Local verification passed 48 unit tests and all 7 UI tests in a clean regular
iPhone Simulator run. All seven UI scenarios also have passing small-iPhone
evidence across the suite and targeted regressions, and the unsigned iPhone
Release build passes. Result bundles are kept in `artifacts/ios/`; the status
document identifies the exact runs. Check the branch's
[GitHub iOS workflow](https://github.com/hetptl1433/sparc/actions/workflows/ios.yml?query=branch%3Afeat%2Fnative-ios-controller)
for remote CI results.

## Run on a Mac

1. Install Xcode with an iOS Simulator runtime.
2. Open `ios/SPARC.xcodeproj` and choose the **SPARC** scheme.
3. Choose an iPhone Simulator and press Run. No signing account is needed for a simulator.
4. For your iPhone, choose your Apple Developer team in the SPARC target's
   **Signing & Capabilities**, choose a unique bundle identifier if necessary,
   select the connected phone, and Run.

The checked-in Xcode project has no external Swift dependencies or project-generator
installation requirement. It includes the application, unit tests, UI tests, asset
catalog, privacy manifest, and a shared scheme. The project is generated by the
small repository script only when source files are added or removed:

```sh
python3 scripts/ios/generate_project.py
bash scripts/ios/test.sh
```

## Daily use

- **Home:** current charge state, battery, realistic vehicle, target and ready time,
  monthly savings estimate, current rate, and overnight plan. Its button always says
  **Charge now**, including while waiting or when a charge has finished.
- **Current schedule:** the small calendar button on the vehicle card opens the
  summary. **Update just today** saves a temporary departure and target.
  **Change weekly schedule** edits the saved routine. A temporary goal expires at
  its departure without changing the routine.
- **Charge:** immediate charge, pause, resume, and end controls with confirmation.
- **Plan, Insights, Records:** the remaining daily-use tabs. Sample charts and
  session examples appear only in demo mode; live views avoid invented data.
- **Settings:** pair or reconnect the home controller, configure Wi-Fi, choose demo
  or controller mode, and remove this iPhone's saved pairing.

All schedule times use **America/Chicago**, including daylight-saving transitions.
The ready buffer is 30 minutes before departure. The iPhone edits and displays the
configuration; the Raspberry Pi remains the place for charging decisions.

## Connect a Raspberry Pi 4

Install and start the [companion service](../controller/README.md) on Raspberry Pi
OS with Bluetooth and NetworkManager. On the iPhone, open **Settings → Connect
home controller**, scan nearby devices, connect to your Pi, enter its setup key,
and send its Wi-Fi details. Keep both devices nearby during setup. The app saves
the pairing only after the Pi answers an authenticated request on the local network.

Bluetooth permission is requested when starting setup. Local network access is
requested when connecting to the Pi. If access is denied, the setup flow explains
how to open iOS Settings. A simulator cannot verify real Bluetooth hardware; use
an iPhone for that part.

The setup key is kept in this iPhone's Keychain. Wi-Fi credentials are sent in an
authenticated encrypted message and are not stored in UserDefaults or printed to
logs. The controller protocol also encrypts local network messages and rejects
replays. The [protocol document](../docs/ios/CONTROLLER_PROTOCOL.md) explains the
trust boundary and key rotation.

## Current hardware integration boundary

The app and companion implement pairing, Wi-Fi provisioning, authenticated local
connectivity, and durable schedule settings. The existing SPARC research planner
and Tesla vehicle authorization/control are not yet wired to the companion.
Until a real vehicle adapter supplies telemetry and acknowledges commands, live
mode shows unavailable data and reports the missing adapter. Demo mode starts in
**Waiting for a better charging time** on every fresh launch, as requested for the
design, and never sends hardware commands.

There is no account server, analytics SDK, Tesla sign-in impersonation, or claimed
Apple Calendar integration. The native app is buildable in the iOS Simulator;
see the [status document](../docs/ios/STATUS.md) for the latest executed tests.
An App Store/TestFlight upload additionally needs your signing identity and the
physical-device checklist in the [QA guide](../docs/ios/QA.md).

## Assets

`Cybertruck.imageset/cybertruck.png` is the transparent render used in the approved
design. It is a generated illustration, not an official Tesla application asset.
`CybertruckView` draws the light bar independently so it is truly off when waiting,
paused, complete, unplugged, or offline.
